# AGENTS.md — for AI coding agents

This repo follows a spec-driven workflow so any agent (Claude Code, Codex, Cursor,
Hermes, Gemini, etc.) can pick up where the last one left off.

## Start here

1. Read `specs/shiro-portfolio/SPEC.md` — project metadata + the canonical reading order.
2. Follow `entry_order` in SPEC.md (requirements → design → BUILD_PLAN).

## Conventions

- Specs live in `specs/<project>/` — agent-agnostic, not tied to any single tool.
- `SPEC.md` is the index (YAML frontmatter: name / workflow / type / status + entry order).
- `BUILD_PLAN.md` is the **living** plan. If the repo is partially built, EXTEND it
  (append a status checkpoint + new deltas) — never rewrite it from scratch.
- Stack: Nuxt 4 (SSG/prerendered) + Pinia + `@nuxtjs/i18n` (en/es/am) + `@vite-pwa/nuxt`
  + `nuxt-security` + `@nuxtjs/seo` + Tailwind v4 + M3 design tokens.
- UI follows **M3 atomic design, built bottom-up**: Atom (`A*`) → Molecule (`M*`) →
  Organism (`O*`) → Page. **Pages compose organisms** — never inline section markup or
  data inside a page. (See the `atomic-design-order` skill.)
- **i18n lockstep**: every user-facing string is a key in `i18n/locales/{en,es,am}.json`.
  Never hardcode English in a component; add a new string to all three files in one change.
  `detectBrowserLanguage` MUST be `false`. (See the `nuxt4-i18n-locale-pitfalls` skill.)
- Aesthetic follows the M3 palette (see the `viral-m3-aesthetics` skill). Tokens are
  generated by `npm run generate:theme` → `app/assets/css/material-tokens.css` (do not hand-edit).
- Conventional commits (`feat:` / `fix:` / `chore:`), commit + push after each change.

## Definition of done

A phase is done when: tests pass (`npm run test:unit`, `npm run test:e2e`), the build
succeeds (`npm run generate`), the work is committed + pushed, AND its `[ ]` checkboxes in
`specs/shiro-portfolio/BUILD_PLAN.md` are flipped to `[x]` (so the next agent resumes from
the plan instead of re-auditing the whole repo).
